# MVP 기능별 결정 사항

2026-11-04 핸드오프 문서(`namaste-world-handoff.md`)를 바탕으로 기능별 미정 항목을 논의해 정한 내용입니다. 기획 기준 문서인 `design/game-brief.md`는 아직 저장소에 없습니다. 그래서 기능은 핸드오프와 draw.io 기획서의 페이지 구성을 보고 나눴고, 브리프가 들어오면 MVP 6개 항목과 다시 맞춰 봐야 합니다.

## 요약

| #   | 기능             | MVP      | 핵심 결정                                                                             |
| --- | ---------------- | -------- | ------------------------------------------------------------------------------------- |
| 1   | 신호 수집        | 포함     | 훅이 앱의 로컬 HTTP 서버로 이벤트를 보냄. Claude Code와 Codex 둘 다 지원              |
| 2   | 캐릭터 반응      | 포함     | 대기, 작업 중, 마우스 반응. 에러와 거부는 따로 반응. three.js 로우 폴리 3D            |
| 3   | 성장             | 포함     | 레벨 대신 연봉(LPA)으로 표시. 실시간 XP                                               |
| 4   | 직군             | **제외** | 마일스톤 2에서 논의                                                                   |
| 5   | 꾸미기           | 포함     | 연봉이 오를 때 아이템이 자동으로 해금됨. 세부 목록은 `/design-system 꾸미기`에서 정함 |
| 6   | 하루 마무리 영상 | 포함     | 퇴근 버튼 또는 자정. 자막 위주의 짧은 3D 연출                                         |
| 7   | 앱 형태          | 포함     | 투명 창과 트레이. macOS, Windows                                                      |

## 1. 신호 수집

### 결정

- **전달 방식은 HTTP입니다.** 앱이 `127.0.0.1`에 작은 HTTP 서버를 열고, Claude Code와 Codex의 훅이 이벤트를 POST로 보냅니다.
- **앱이 켜져 있을 때만 XP를 줍니다.** 앱이 꺼져 있을 때 들어온 이벤트는 버립니다. 나중에 몰아서 반영하지 않습니다.
- **훅은 앱이 버튼 하나로 설치합니다.** "연결하기"를 누르면 앱이 `~/.claude/settings.json`과 Codex 훅 설정에 훅을 추가합니다. "연결 해제"로 다시 뺄 수 있고, 사용자가 원래 넣어 둔 훅은 건드리지 않습니다.
- **Claude Code와 Codex를 처음부터 함께 지원합니다.**

### 확인한 사실

- 이 Mac의 Codex는 `codex-cli 0.131.0`이고 훅을 쓸 수 있습니다. `~/.codex/config.toml`의 `[features]`에 `hooks = true`가 있고, `~/.codex/hooks.json`에 이미 `Stop` 훅이 등록되어 있습니다.
- 핸드오프 조사에 따르면 Claude Code 로그는 `tool_use`와 `tool_result.is_error`를 믿을 수 있습니다. 다만 에러의 약 30%는 훅 차단이나 사용자 거부입니다.
- 핸드오프 조사에 따르면 이 Mac의 Codex 로그에는 도구 이벤트가 없습니다. 그래서 Codex는 훅으로만 신호를 받습니다.

### 구현할 때 정할 것

- **훅이 Claude를 느리게 하지 않아야 합니다.** 앱이 꺼져 있으면 훅 요청은 실패합니다. 훅 명령에 아주 짧은 타임아웃을 주고, 실패해도 조용히 끝나게 합니다.
- **포트**: 고정 포트를 쓸지, 앱이 고른 포트를 파일에 적어 두고 훅이 읽게 할지 정해야 합니다.
- **보안**: 서버는 `127.0.0.1`에만 엽니다. 다른 로컬 프로세스가 가짜 이벤트를 보내지 못하게 설치할 때 만든 토큰을 훅 요청에 넣을지 정해야 합니다.
- Codex 훅이 보내는 이벤트 종류(`PreToolUse`, `PostToolUse` 등)와 입력 형식이 Claude Code와 얼마나 같은지 확인해야 합니다.
- 세션은 세션 ID별로 추적합니다. 60초 동안 신호가 없으면 끝난 것으로 보고, 같은 이벤트는 도구 호출 ID로 한 번만 셉니다(핸드오프 조사 그대로).

## 2. 캐릭터 반응

### 결정

- **MVP 상태는 대기와 작업 중입니다.** 세션이 없으면 대기 모션, 도구가 돌면 작업 모션을 보여 줍니다.
- **마우스를 올리면 반응합니다.** 캐릭터가 커서 쪽을 보거나, 졸던 눈을 뜨는 식입니다.
- **에러와 거부는 따로 반응합니다.** 진짜 도구 에러에는 당황하는 반응을 보여 줍니다. 훅 차단과 사용자 거부에는 "Sorry sir, kindly approve" 같은 다른 반응을 보여 줍니다.
- **대사는 가끔 말풍선으로 띄웁니다.** 에러, 연봉 인상, 오랜만의 작업 같은 순간에만 힝글리시 대사를 잠깐 보여 줍니다.
- **그림은 three.js 로우 폴리 3D입니다.** 3D 에셋은 직접 만듭니다.

### 나중에 정할 것

- 동시 세션이 여러 개일 때의 "더 바빠 보이는" 연출. 모니터를 늘리거나 뒷모습을 보여 주는 방식은 이미 제외했습니다.
- 졸기(오래 쉼) 상태를 MVP에 넣을지. 마우스를 올려 "눈 뜨기"를 하려면 졸고 있는 상태가 먼저 있어야 해서, 대기 모션 안에 가볍게 넣는 방법도 있습니다.
- 에셋 파일 형식(glTF 권장), 파츠를 나누는 단위, 애니메이션을 어디서 만들지(Blender 안인지, 코드 트윈인지).

## 3. 성장

### 결정

- **레벨 대신 연봉(LPA)으로 보여 줍니다.** 단계마다 직급 이름을 함께 붙입니다.
- XP는 대화가 진행되는 동안 실시간으로 쌓고, 세션이 끝날 때 주는 점수는 없습니다.
- 작업 유형 판정(버그 수정, 기능, 키워드 등), 세션 기본점, 연속 접속 배율은 쓰지 않습니다.
- 성장 속도는 "초반에는 빠르게, 갈수록 느리게"로 정했습니다. 기존 agent pet을 참고했습니다.

### XP 규칙 (초안)

[ClaudeXP](https://github.com/EvanPaules/ClaudeXP) 규칙에서 확실한 신호만 가져왔습니다.

| 신호                       | XP                  | 세션당 상한 |
| -------------------------- | ------------------- | ----------- |
| 도구 사용 1회              | +5                  | 100 (20회)  |
| 새로 쓰거나 고친 파일 1개  | +10                 | 80 (8개)    |
| 한 세션에서 도구 20회 도달 | +30 (그 순간 한 번) | 30          |

세션 하나로 얻을 수 있는 XP는 최대 210입니다.

### 성장 곡선 (초안)

이 Mac의 최근 30일 Claude Code 로그에 위 규칙을 적용해 보니, 사용한 날(9일)의 하루 XP 중간값은 약 160이었습니다(하위 25% 130, 상위 25% 210). 다만 표본이 적고, 데스크톱 앱 세션이 모두 이 로그에 들어 있는지는 확인하지 않았습니다. 하루 160~200 XP를 기준으로 다음 목표에 맞췄습니다.

- 첫날 2번 오릅니다.
- 첫 주(약 1,000 XP)에 7~8단계에 도착합니다.
- 한 달 뒤부터는 일주일에 한 번쯤 오릅니다.

| 단계 | 누적 XP | 연봉   |
| ---- | ------- | ------ |
| 1    | 0       | 3 LPA  |
| 2    | 50      | 4 LPA  |
| 3    | 120     | 5 LPA  |
| 4    | 220     | 6 LPA  |
| 5    | 350     | 8 LPA  |
| 6    | 520     | 10 LPA |
| 7    | 740     | 12 LPA |
| 8    | 1,020   | 15 LPA |
| 9    | 1,370   | 18 LPA |
| 10   | 1,800   | 22 LPA |
| 11   | 2,320   | 26 LPA |
| 12   | 2,940   | 30 LPA |
| 13   | 3,670   | 36 LPA |
| 14   | 4,520   | 42 LPA |
| 15   | 5,500   | 50 LPA |

- 단계 수는 해금할 꾸미기 아이템 수에 맞춰 늘리거나 줄입니다. 15단계 다음은 간격을 더 넓혀 이어 갑니다.
- 직급 이름(인턴, 트레이니, SDE-1 등)은 아직 정하지 않았습니다.
- 참고: [Clawdagotchi](https://github.com/cpenned/clawdagotchi)는 8단계(100~6,000 XP)이고, 단계마다 액세서리를 하나씩 해금합니다. ClaudeXP는 15단계(500~157,000 XP)입니다.

## 4. 직군 (MVP 제외)

MVP에서는 직군 선택을 넣지 않습니다. **마일스톤 2에서 논의합니다.** 논의할 때 볼 항목입니다.

- 직군에 따라 달라지는 것: 시작 옷과 소품, 대사, 직급 이름, 전용 아이템. 능력치 효과는 없습니다(이미 정함).
- 고르는 시점과 바꿀 수 있는지.
- 플레이어가 직접 고르고, 자동 판정은 하지 않습니다(이미 정함).

## 5. 꾸미기

### 결정

- **연봉이 오를 때 아이템이 자동으로 해금됩니다.** 재화와 상점, 랜덤 상자는 없습니다.
- 아이템은 꾸미기 전용(캐릭터 옷, 책상, 방)이고 능력치 효과가 없습니다. 대신 파츠와 색상 변형으로 수량을 늘립니다(이미 정함).

### 나중에 정할 것

- 파츠 슬롯, 아이템과 방 목록, 단계별 해금표는 `/design-system 꾸미기`에서 정합니다.
- 한 단계에 몇 개씩 해금할지. 색상 변형도 따로 세는지.

## 6. 하루 마무리 영상

### 결정

- **하루가 끝나는 때**: 사용자가 "퇴근" 버튼을 누르면 바로 보여 줍니다. 누르지 않았으면 자정에 하루를 닫고, 다음 날 처음 앱을 켤 때 전날 영상을 보여 줍니다.
- **형태**: 앱 안에서 three.js로 연출합니다. 공들인 애니메이션이 아니라, 캐릭터가 고개만 까딱이며 웅얼거리고 **자막으로 하루를 되짚는** 방식입니다. 인도 튜토리얼 유튜브의 말투("Hello friends, today we will learn...")를 빌립니다.
- 파일로 내보내기는 MVP에 넣지 않습니다.

### 나중에 정할 것

- 자막에 넣을 수치: 도구 사용 수, 고친 파일 수, 에러 수, 오른 연봉 등.
- 길이(20~30초 안팎으로 가정), 건너뛰기 버튼.
- "자정"을 기기의 현지 시간으로 볼지. 자정을 넘겨 일할 때 어느 날로 셀지.

## 7. 앱 형태

### 결정

- **투명 창과 트레이**: 배경 없는 작은 창에 캐릭터와 책상만 띄웁니다. 항상 위에 둘지는 설정으로 고릅니다. 꾸미기, 기록 화면은 트레이 메뉴에서 여는 별도 창으로 만듭니다.
- **지원 OS**: macOS와 Windows.

### 구현할 때 정할 것

- 투명 창과 three.js(WebGL)가 macOS WKWebView와 Windows WebView2에서 모두 잘 도는지 먼저 확인합니다.
- 투명한 부분을 클릭하면 아래 창으로 넘어가게 할지(클릭 통과).
- 저장 위치. 진행 상황은 로컬에만 저장하는 것으로 가정합니다.
- 지금 템플릿 이름(AI Buddy, `com.aibuddy.app`)을 Namaste World로 바꿀지.

- 위 "나중에 정할 것"과 "구현할 때 정할 것"의 항목들.
