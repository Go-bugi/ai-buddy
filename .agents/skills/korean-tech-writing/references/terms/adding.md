# 용어 추가하기

두 가지 경우가 있습니다.

- **용어 하나를 추가할 때**: 작업 중 용어집에 없는 단어를 판단했고, 반복해서 나올 것 같은 경우
- **프레임워크 파일을 새로 만들 때**: `terms/`에 파일이 없는 프레임워크의 글을 반복해서 쓰거나 번역하게 된 경우

핵심은 **감으로 정하지 않는 것**입니다. 공식 한국어 문서가 실제로 어떤 표기를 쓰는지 세어 보면 논쟁할 일이 없습니다.

## 용어 하나를 추가할 때

1. [common.md](common.md)의 판단 순서대로 표기를 정합니다.
2. 사용자에게 정한 표기와 근거를 보여주고 추가해도 되는지 묻습니다. 용어집은 사용자의 기준이라 확인 없이 고치지 않습니다.
3. 승인되면 알맞은 절에 한 줄 추가합니다. 공통 용어면 `common.md`, 프레임워크 고유 개념이면 그 프레임워크 파일입니다. 공식 번역어를 두고 현업 표기를 택했다면 `common.md` 6절에 넣습니다.
4. 실측 수치가 있으면 함께 적고, 없으면 칸을 비워 둡니다. 추측한 숫자를 적지 않습니다.

## 프레임워크 파일을 새로 만들 때

### 만들 가치가 있는지 먼저 봅니다

만들 가치가 있는 경우:

- 고유 개념어가 10개 이상이고, 그중 한국어 표기가 갈리는 게 있다
- 문서 사이트가 자체 마크다운 확장을 쓴다 (VitePress 컨테이너, MDX 커스텀 컴포넌트, 헤딩 앵커 문법 등). 번역할 때 보존 대상 목록이 필요합니다
- 앞으로도 그 프레임워크의 글을 반복해서 쓰거나 번역할 것 같다

애매하면 만들지 않는 쪽이 낫습니다. 파일이 늘어날수록 어느 걸 읽어야 할지 판단하는 비용이 커집니다.

### 1. 기준이 될 한국어 문서를 찾습니다

우선순위대로 봅니다.

1. **공식 번역 저장소**: `vuejs-translations/docs-ko`, `reactjs/ko.react.dev`처럼 원본 마크다운이 통째로 있는 곳. 가장 좋습니다.
2. **공식 한국어 문서 사이트**: 저장소를 못 찾으면 사이트에서 대표 페이지 몇 개를 받습니다.
3. **둘 다 없을 때**: `common.md`만 적용하고, 그 프레임워크 고유 개념어는 전부 원문 유지로 갑니다. 근거 없는 표기표는 없느니만 못하니 파일을 억지로 만들지 않습니다.

### 2. 빈도를 실측합니다

`scripts/measure-terms.sh`가 저장소를 받아 표기 빈도를 셉니다. 경로는 스킬 폴더 기준입니다.

```bash
scripts/measure-terms.sh <git-url> <content-path> [terms-file]
scripts/measure-terms.sh https://github.com/vuejs-translations/docs-ko.git src
```

출력은 세 부분입니다.

- **문체**: `~합니다` / `~해요` / `~한다` / `~하세요` 분포
- **번역투 흔적**: `되어집니다`, `당신의`, `우리는` 등의 출현 횟수. 수치가 높으면 그 문서는 문체 기준으로 부적합하니 용어만 참고합니다
- **용어**: 후보 표기별 출현 횟수. 갈리는 항목은 우세한 쪽을 고릅니다

프레임워크 고유 용어를 더 세고 싶으면 한 줄에 하나씩 적은 파일을 세 번째 인수로 넘깁니다.

### 3. 조사를 정합니다

영어 표기마다 한국어로 읽었을 때의 받침을 적습니다. 실무에서 가장 자주 틀리는 부분이라 표로 만들어 두면 값이 큽니다. 두 조사를 각각 세서 어느 쪽이 압도적인지 보면 확정됩니다. `state를` 342회 대 `state을` 1회처럼요.

### 4. 파일을 씁니다

아래 양식을 `terms/<이름>.md`로 저장해 채웁니다. 파일명은 소문자 케밥 케이스입니다 (`vue.md`, `svelte.md`, `nextjs.md`).

**수치 없는 항목은 넣지 않습니다.** 근거 없이 적어 두면 다음에 볼 때 실측인지 추측인지 구분이 안 됩니다.

### 5. SKILL.md를 갱신합니다

SKILL.md 구조도의 `terms/` 목록에 새 파일을 한 줄 추가합니다. 그래야 다음 작업에서 그 파일이 있다는 걸 알 수 있습니다.

## 프레임워크 파일 양식

````markdown
# {프레임워크 이름}

기준 문서: {공식 한국어 문서 사이트 또는 저장소, 측정한 경로}

아래 수치는 그 저장소의 원본 마크다운에서 직접 센 출현 횟수입니다. 공통 용어와 조사 일반 규칙은 [common.md](common.md)에 있습니다. 두 곳이 어긋나면 이 파일이 우선입니다.

## 1. 원문 유지: 고유 개념어

한글로 옮기면 산문과 코드의 연결이 끊어지는 것들. API 이름, 지시자, 예약어.

| 영어 | 표기 | 실측 |
|---|---|---|

## 2. 고유 개념

번역하거나 음차하는 쪽이 자연스러운 개념어.

| 영어 | 한국어 | 실측 |
|---|---|---|

## 3. 조사 결정표

| 표기 | 읽는 소리 | 받침 | 을/를 | 은/는 | 이/가 |
|---|---|---|---|---|---|

## 4. 번역할 때 손대면 안 되는 것

**헤딩 앵커**: {`{#anchor}`, `{/*anchor*/}`, 자동 생성 등}

**템플릿 문법**: {`v-if`, `{#each}`, `{{ }}` 등}

**문서 사이트 확장**: {VitePress `::: tip`, MDX 커스텀 컴포넌트 등. 출현 빈도순}

**프론트매터**: {번역할 키와 유지할 키}

**내부 링크**: {경로 체계가 원문과 같은지}

## 5. 문체 실측

| 항목 | 수치 |
|---|---|
| `~합니다` / `~습니다` | |
| `~하세요` | |
| `~해요` | |
| `~한다` | |
| 헤딩 중 `~하기` 형태 | |
| 코드 주석 중 한국어 | |

번역투 흔적: {`되어집니다`, `당신의`, `우리는` 등의 횟수}

## 6. 생태계 라이브러리

{이 프레임워크 위에서 도는 라이브러리를 다룰 때의 기준. 공식 한국어 문서가 있으면 따르고, 없으면 고유 개념어는 원문 유지}
````
