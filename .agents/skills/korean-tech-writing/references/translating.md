# 번역하기

영어 원문(기술 문서, README, 릴리스 노트, 블로그 글, RFC)을 한국어로 옮길 때만 읽는 파일입니다. 용어와 문장 규칙은 새로 쓸 때와 같고, 여기에는 **번역에만 있는 단계**를 적었습니다.

## 1. 원문을 확보합니다

| 입력 | 처리 |
|---|---|
| URL | WebFetch로 가져옵니다. 요약본이 아니라 원문 전체가 필요하므로, 문서 소스가 GitHub에 있으면 `raw.githubusercontent.com`의 md/mdx를 직접 받는 쪽이 정확합니다. |
| 로컬 md/mdx 파일 | Read로 읽습니다. 출력 경로를 사용자가 지정하지 않았으면 어디에 쓸지 먼저 확인합니다. 원본을 덮어쓰지 않습니다. |
| 붙여넣은 텍스트 | 번역해 대화창에 출력합니다. 파일로 만들지 않습니다. |

## 2. 어느 프레임워크 문서인지 확인합니다

| 상황 | 처리 |
|---|---|
| `terms/<이름>.md`가 있다 | 그 파일을 먼저 읽습니다. 공식 한국어 번역에서 실측한 표기와 보존 대상이 들어 있습니다 |
| 없다 | `terms/common.md`만으로 진행하되, 그 프레임워크 고유 개념어는 원문 유지가 안전합니다. 끝난 뒤 [terms/adding.md](terms/adding.md)를 참고해 파일을 만들지 사용자에게 제안합니다 |
| 프레임워크 중립 문서 (MDN, TypeScript 핸드북, 일반 JS 글) | `terms/common.md`만으로 충분합니다 |

여러 프레임워크가 섞인 문서(React에서 Vue로 마이그레이션하는 글 등)라면 각 코드와 개념이 속한 쪽의 표기를 따릅니다.

분량이 많으면 섹션 단위로 나눠 진행하되, 먼저 전체를 훑어 개념어 목록을 잡고 시작합니다. 용어는 문서 전체에서 일관되어야 합니다.

## 3. 손대면 안 되는 것을 먼저 표시합니다

번역하기 전에 보존 대상을 식별해 두면 나중에 되돌리는 일이 없습니다.

**번역하지 않는 것**

- **헤딩 앵커**: 헤딩 옆 URL 프래그먼트 지정자. `## Adding state {/*adding-state*/}`(react.dev), `## Adding state {#adding-state}`. 번역하면 문서 안팎의 링크가 깨집니다.
- **코드 식별자**: 변수, 함수, 컴포넌트, prop 이름, import 경로, 파일명, 패키지명.
- **문자열 리터럴**: 코드가 실제로 출력하거나 비교하는 값. 바꾸면 예제가 다르게 동작합니다.
- **템플릿 문법과 어트리뷰트 이름**: JSX의 `<button onClick={...}>`, Vue의 `v-if`·`:prop`·`@click`, Svelte의 `{#if}`·`bind:`.
- **문서 사이트 커스텀 태그**: MDX 컴포넌트, VitePress 컨테이너. 태그는 그대로 두고 **안의 산문만** 번역합니다.
- **링크 URL**: 대괄호 안 라벨만 번역하고 괄호 안 주소는 유지합니다.
- **프론트매터 키**: `title:`, `description:` 같은 키 이름. 값은 번역하고 플래그성 값(`draft: true`)은 유지합니다.

**번역하는 것**

- 산문, 헤딩 텍스트, 표 내용, 이미지 `alt` 텍스트
- **코드 블록 안의 주석**: `// You can't do this` → `// 이렇게 하면 안 됩니다`. 주석은 설명이라 번역해야 독자에게 값이 있습니다. ko.react.dev도 `//` 주석 1,748줄 중 959줄이 한국어입니다.

## 4. 번역할 때 특히 신경 쓸 것

[sentences.md](sentences.md) 3절 번역투 규칙이 번역에서 가장 효과가 큽니다. 그중에서도 **긴 문장 쪼개기**가 핵심입니다. 원문 한 문장이 한국어 두세 문장이 되는 건 오역이 아니라 정상입니다.

애매한 상황에서는 이렇게 합니다.

- **원문이 틀렸거나 낡았을 때**: 원문대로 옮기되, 결과와 별도로 사용자에게 어느 부분이 이상한지 알립니다. 문서 안에 역주를 임의로 넣지 않습니다.
- **대응하는 한국어 용어가 없을 때**: 원문을 유지하고 처음 나올 때만 짧게 풀어 씁니다.
- **농담, 비유, 말장난**: 직역하면 대부분 죽습니다. 한국어에서 자연스럽게 살릴 수 있으면 바꾸고, 안 되면 담백한 설명문으로 내립니다. 억지 말장난은 만들지 않습니다.
- **이미 번역된 문서를 다듬어 달라는 요청**: 전면 재번역이 아니라 규칙 위반 지점만 고칩니다. 무엇을 왜 고쳤는지 함께 보고합니다. 원문이 없으면 번역투 판단 근거가 약하니 SKILL.md의 `humanizer` 단계 위주로 봅니다.

## 5. 번역 전용 점검 항목

SKILL.md의 공통 점검에 더해 아래를 확인합니다. 앞의 세 개는 깨지면 문서가 망가지므로 반드시 봅니다.

- [ ] 헤딩 앵커가 전부 원문 그대로인가
- [ ] 코드 블록 안 식별자, 문자열, import 경로가 바뀌지 않았는가 (주석만 한국어인가)
- [ ] 마크다운 링크의 URL이 유지되었는가
- [ ] 원문의 조건, 예외, 경고가 빠지지 않았는가
- [ ] 번역 중 새로 정한 용어가 있으면 사용자에게 알렸는가
